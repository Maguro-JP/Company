# オーナーのクリエイティブツールのシリーズ（部署の単位で分ける）

オーナーは、同じ決まり（置き場、配布、起動、Ciel のスキル）で作ったツールを一つのシリーズとして育てている。
Company はその一員で、ほかのツールを「相手が得意なこと」に使う。
ここは、部門 → 部署 → 仕事の単位まで分けた台帳。Company は部署ごとに役職（担当の AI）を置き、
仕事の単位ごとに相手のツールの口（MCP の道具）を当てる。1 つの部署が 1 つの口を持つ形にしておくと、
ツールが増えても部署を足すだけで済み、責任の境界がツールの境界と一致する。

public のリポジトリなので、公開しているツールだけを名前で書く。非公開のものは作業場の `data/partners.json` に置く。

## 共通の決まり（シリーズ全体）

- 置き場: プログラムは `C:\Program Files\<App>`、設定・記録・部品は `C:\ProgramData\<App>`、模型は `C:\LLM`（`gguf\`、`huggingface\`）で共有
- 配布: NSIS の Setup.exe。Linux の Actions で組み、Windows のランナーで入れて起動まで見てから Release に置く。更新はアプリの「更新を確かめる」
- 起動: アプリのウィンドウ（pywebview、Electron、PySide6）。CLI にしない。ショートカットを 1 つ置く
- 連携: ユーザーの設定作業を要らせない。相手が入っていれば置き場を自動で探し、口（HTTP、MCP、ファイル）だけでつなぐ。相手の中身には触らない
- 作業の決まり: どのリポジトリにも Ciel のスキルと CLAUDE.md が入り、同じ働き方で開発する

## 部門と部署

会社の木そのものは `org.yaml`（親会社 → 子会社 → 部門 → 部署 → 課）にあり、画面の「会社の形」と `/api/org` がそれを使う。この表は、課に当てる仕事の単位と席の id の一覧。

状態の列は、○ が今ある口、△ が相手はあるが口が無い、空欄がこれから作るもの。
「席の id」は `company/partners.py` の相手の id で、役職の AI から `<席の id>__<道具>` で見える名前になる。

## 席の付け方（新しいツールができたとき）

1. この表の「仕事の単位」に合う行を見つける。無ければ部署を 1 行足す
2. `company/partners.py` の既定に同じ id で席を足す（`planned` を外し、置き場の自動検出と口を書く）
3. 自動検出は Setup.exe の鍵（`HKLM\Software\<App>\InstallDir`）、Program Files、`C:\<App>` の順
4. 役職の AI の指示（agents/*.md）に、その部署の道具を使う場面を 1 行足す
5. 動いた物だけを「状態」に ○ で書く
