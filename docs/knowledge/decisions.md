# 設計の判断

| 日付 | 判断 | 理由 | 採らなかった案 |
|---|---|---|---|
| 2026-10-25 | 権限は「実行が既定」。止めたい項目だけ false | 「提案して人間が承認」では何も作られなかった | 承認キュー方式（都度承認） |
| 2026-10-25 | 「禁止」と「手段が無い」を分ける（`blocked_on_owner`） | 混ぜるとエージェントが本来できる作業まで自粛する | human_authority に一本化 |
| 2026-10-25 | ツール呼び出しループは自前。プロバイダ非依存 | Claude Agent SDK は Anthropic 専用でローカル LLM が使えない | Agent SDK を Anthropic 時だけ使う二系統 |
| 2026-10-25 | 推論エンジンを同梱し、モデルはアプリ内で取得 | 「別ソフトを入れて起動しておく」前提を置かない | Ollama 必須 |
| 2026-10-25 | 内蔵エンジンのツール呼び出しはプロンプト駆動で自前解釈 | GGUF ごとのチャットテンプレートの function calling 対応に左右されない | llama.cpp の chat_format 依存 |
| 2026-10-25 | 外から会社を操作する関数は controls.py の1表 | Gemini と MCP で二重になりかけた。入口ごとに違う操作ができると追えない | 入口ごとに定義 |
| 2026-10-25 | AdaptiveAIStudio とは MCP（HTTP）で繋ぐ | AAS 側が「相手ごとの専用の口を書かない」方針 | AAS の HTTP API を直接叩く専用連携 |
| 2026-10-25 | 実装系の役職だけ write_file を持つ | 報告と実行が同じ権限だと、自分の作業を自分で承認する構造になる | 全役職に同じツール |
| 2026-10-26 | 費用の歯止めは「1役職の実行あたりのトークン上限」（既定 0 = 無制限） | 放置して回す前提では止まる条件が要る。金額はプロバイダごとに単価が違うので、共通の単位であるトークンで切る | 金額（USD）上限、サイクル全体の上限 |
| 2026-10-27 | 実行の実績は data/runs.csv に役職ごと1行で残し、review の共有コンテキストに直近 8 行を載せる | 「どれだけ回ったか」を推測ではなく数字で見せる。metrics.csv は事業の数字（現金・ユーザー）用なので混ぜない | metrics.csv への自動記入、ランごとの JSON |
| 2026-11-07 | プロバイダの失敗は種類（auth / rate_limited / quota_exhausted / model_missing / context_too_long / unavailable / timeout）に正規化して人の言葉で出し、繋ぐ時間（10 秒）と一覧（5 秒）と生成（10 分）の待ち時間を分け、「本当に答えるか確かめる」で 1 問送って確かめる | AdaptiveAIStudio の providers/errors.ts と net-why.ts、ask-once.ts を参考にした。止まっている相手に生成の待ち時間で 10 分待つ、生の errno では次の一手が分からない、設定が合っているかは送るまで分からない、の 3 つを同じ形で避ける | 1 つの timeout、生の HTTP ステータスの表示、画面で手で送って確かめる |
| 2026-11-07 | クラウドの AI は OpenAI 互換の 1 実装に URL と鍵の環境変数名を足したプリセットで扱い、役職ごとに上書きできる | サービスごとに実装を持つと保守が増える。役職によって向く AI が違う（判断は強いモデル、実装は安いモデル） | サービスごとの専用クラス、全役職で同じモデル |
| 2026-11-07 | 配布版の置き場は Program Files（プログラム、書き換えない）、ProgramData\Company（作業場、AI が書き換える）、C:\LLM\gguf（模型、共有）に分ける。更新は作業場に無い物だけ足し、ある物は書き換えない。前の版（LOCALAPPDATA）からは Setup.exe が移す | AdaptiveAIStudio・CharacterDesigner と同じ並び（shared-models）。利用者名が全角だと AppData の道で llama.cpp が模型を開けない。AI が直したプロダクトと記録を更新で消さない | LOCALAPPDATA に全部入れる（v0.1.x）、モデルをアプリごとに持つ |
| 2026-11-07 | キャラクターの絵とアイコンは外部の画像生成（Figma の generate_image。Canva は枠切れ）で描き、白い背景を抜いた PNG を ui/characters/ に置く。画面は絵を `<img>` で出し、無ければ SVG の姿に落ちる | 自前の SVG では魅力が出ない。CharacterDesigner の chatdraw は手元の GPU と模型が要り、この環境では動かせない。同じちびキャラの画風で 6 人そろえ、絵が無い役職でも画面が壊れないようにする | 自前の SVG のまま、HTML に Base64 で埋める、CharacterDesigner で描く |
| 2026-11-07 | 役職をキャラクター（SVG）で見せ、考えている・話している・ツールを使っている・終わった・落ちた、を CSS の class で動かす | 誰が今動いているかを、ログの文字を読まなくても分かるようにする。動きは CSS だけにして、流れる文字の描画と JS の仕事を増やさない | 画像のファイル、JS のアニメーション、動きなし |
| 2026-11-07 | 配布は NSIS の Setup.exe（埋め込み Python と wheel を同梱、`%LOCALAPPDATA%\Programs\Company`、管理者権限なし）。Linux で組み、Windows のランナーで入れて起動まで見てから Release に置く | CharacterDesigner の packaging と同じ組み方。手元に Windows が無いので、確認は Actions の Windows ランナーで行う | PyInstaller、zip 配布、手元で組む |
| 2026-11-07 | 「テストが落ちた状態でコミットしない」は run_command が git commit の前にテストを走らせて止める | 役職への指示だけでは守られない。AdaptiveAIStudio のハーネスと同じく、実行の手前で止める | コミット後にテストして revert、役職の指示を強める |
| 2026-11-02 | 通知は incoming webhook に JSON 1 通（text と content の両方を入れる） | Slack と Discord を同じ送り方で済ませる。メールは送信元の設定が要るので後回し。送れなくてもランの成否は変えない | SMTP、Slack API（トークン要） |
| 2026-10-31 | 内蔵エンジンの生成中の文字は delta 出来事で流し、確定した text 出来事で置き換える | 1ターン分まとめて出ると、CPU の 7B では数十秒無反応に見える。llama.cpp のストリームは usage を返さないので字句器で数える | SSE とは別の WebSocket、ターン単位の進捗バー |
| 2026-11-07 | 同じ作者のツールとは、相手が公開している口（HTTP、MCP、ファイル）だけでつなぐ。相手の MCP は用事のたびに起こして閉じ、常駐させない。相手の一覧は既定（公開の物）と作業場の partners.json を重ねる | Microsoft のソフトどうしのように連携できるのが普通。境界で責任を分ければ、Company は不要な部分に手を割かずに済む。非公開のツールの名前は public のコードに書けない | 相手のコードを取り込む、相手の DB を直に読む、連携先をコードに全部書く |
